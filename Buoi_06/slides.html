Model Context Protocol (MCP) là gì?

  • Giao thức kết nối mở do Anthropic khởi xướng (cuối 2024)
  • Được ví như "Cổng USB Type-C của thế giới AI"
  • Chuẩn hóa giao tiếp giữa AI Host và công cụ / dữ liệu bên ngoài
  • Chuyển kiến trúc phức tạp $N \times M$ thành chuẩn kết nối $N + M$
  • Tích hợp sẵn trong Antigravity IDE, Cursor, Claude Desktop
💡 Tương tự USB-C thay thế mọi loại cáp, MCP chuẩn hóa mọi tích hợp của AI Agent.
Hình tượng USB-C giúp học viên hiểu ngay bản chất của MCP là một giao thức chuẩn hóa mở.

3 Thành phần Trụ cột trong MCP

  • Resources: Dữ liệu chỉ đọc (file canvas, DB schema, log hệ thống)
  • Tools: Các hàm thực thi có schema tham số rõ ràng để Agent gọi
  • Prompts: Mẫu câu lệnh chuẩn hóa kích hoạt tác vụ hiệu quả
💡 Resources = GET (đọc dữ liệu); Tools = POST (thực thi hành động có side-effect).
3 trụ cột này định nghĩa toàn bộ khả năng tương tác của MCP Server.

Kiến trúc 3 Tầng của Hệ sinh thái MCP

💡 MCP Host (IDE) kết nối MCP Server thông qua JSON-RPC 2.0 qua Standard I/O hoặc SSE.
Giải thích kiến trúc 3 tầng: Host (IDE), Server (MCP process), Cloud/Tools. Nhờ JSON-RPC 2.0, Host không cần biết Server viết bằng Python hay Node.js.

So sánh Toàn diện: MCP vs. API Truyền thống

API Truyền thống (REST / HTTP)

  • Lời gọi: Dev tự viết code cứng và parse JSON thủ công
  • Khám phá: Schema tĩnh, dev đọc Swagger và hardcode endpoint
  • Làm UI: Tự nhìn mockup rồi gõ tay từng dòng code

Giao thức MCP (JSON-RPC 2.0)

  • Lời gọi: AI Agent tự gọi tool theo ngữ cảnh prompt
  • Khám phá: Schema động, Agent tự phát hiện Tool & Schema
  • Làm UI: Agent đọc Canvas qua MCP, tự sinh code chuẩn xác
Bảng so sánh then chốt: Giúp học viên hiểu rõ bước dịch chuyển từ việc code tay sang chỉ huy Agent.

Giải pháp: Quản lý trạng thái với `st.session_state`

stateful_fix.py 

import streamlit as st

# Khởi tạo an toàn: Chỉ gán lần đầu tiên
if "count" not in st.session_state:
    st.session_state.count = 0

if st.button("Tăng số đếm"):
    st.session_state.count += 1

st.write(f"Số đếm hiện tại: {st.session_state.count}")
Bấm lần 1: count = 1. Bấm lần 2: count = 2. Tăng bền vững!
  • st.session_state là Persistent Dictionary gắn liền phiên duyệt web
  • Lưu giữ giá trị an toàn qua các chu kỳ rerun
  • Toán học chuyển trạng thái: $S_{t+1} = g(S_t, \text{action})$
  • Ứng dụng: Lưu lịch sử chat, bộ đếm request, kết quả API, file upload
Giải thích cú pháp kiểm tra key trong session_state để tránh bị ghi đè dữ liệu.

Kết nối Streamlit với API Backend

Giao tiếp Client-Server qua HTTP POST & Thư viện requests (40 phút)

Bắt đầu Phần 3: Trọng tâm thực hành kết nối mạng Client-Server.

Vòng đời HTTP Request - Response

  • Client (Streamlit): Đóng gói dữ liệu thành JSON và gửi HTTP Request
  • Server (FastAPI): Nhận request, validate schema, suy luận và gửi HTTP Response
  • Phương thức: GET (đọc dữ liệu), POST (gửi dữ liệu/payload lớn)
  • Mã trạng thái: 200 OK, 400 Bad Request, 422 Unprocessable, 500 Error
Ôn tập nhanh vòng đời HTTP: Client gửi Request, Server trả Response.

Ánh xạ Dữ liệu & Chuẩn hóa JSON

$$ \mathcal{T}: \mathcal{X} \xrightarrow{\text{Request}} \mathcal{S}_{\text{JSON}} \xrightarrow{f_\theta} \mathcal{Y} \xrightarrow{\text{Response}} \mathcal{X}' $$

  • $\mathcal{S}_{\text{JSON}}$ chỉ chấp nhận kiểu dữ liệu nguyên thủy (String, Number, Array, Object)
  • Tensor PyTorch $\mathbf{T}$ hoặc NumPy ndarray không thể gửi trực tiếp
  • Bắt buộc chuyển sang list bằng .tolist() hoặc mã hóa Base64
💡 Sinh viên rất hay mắc lỗi nhét thẳng tensor PyTorch vào requests.post() gây crash.
Lưu ý quan trọng về chuyển đổi kiểu dữ liệu trước khi gửi qua API.

Kiến trúc Backend FastAPI Cung cấp sẵn

  • File mẫu có sẵn: Học viên chạy độc lập tại cổng 8000
  • Lệnh chạy: uvicorn backend_api:app --reload --port 8000
  • Gồm 2 endpoint: POST /predict (JSON) và GET /predict-stream (SSE)
  • Kiểm tra qua Swagger UI: http://localhost:8000/docs
💡 Hướng dẫn học viên mở Terminal riêng để giữ cho backend chạy liên tục.
Giới thiệu template backend có sẵn để tiết kiệm thời gian code lại API.

Backend Code: Pydantic Validation

backend_api.py 

from fastapi import FastAPI, HTTPException, status
from pydantic import BaseModel, Field

class TextInferenceRequest(BaseModel):
    text: str = Field(..., min_length=1, max_length=500)

class TextInferenceResponse(BaseModel):
    status: str
    original_text: str
    predicted_label: str
    confidence: float

@app.post("/predict", response_model=TextInferenceResponse)
def predict_endpoint(req: TextInferenceRequest):
    label = "POSITIVE" if len(req.text) % 2 == 0 else "NEGATIVE"
    return TextInferenceResponse(
        status="success", original_text=req.text,
        predicted_label=label, confidence=0.9425
    )
POST /predict ➔ 200 OK: {'status': 'success', 'predicted_label': 'POSITIVE', ...}
  • TextInferenceRequest: Tự động validate kiểu dữ liệu và chặn chuỗi rỗng
  • FastAPI tự động validate dữ liệu, trả lỗi 422 nếu sai schema
  • response_model: Chuẩn hóa dữ liệu trả về theo đúng định dạng định trước
Phân tích backend để học viên thấy rõ schema của trường text cần gửi từ frontend.

04

Streaming Data từ API lên Streamlit

Truyền nhận dữ liệu thời gian thực cho Generative AI & st.write_stream (10 phút)

Bắt đầu Phần 4: Kỹ thuật HTTP Streaming và hiệu ứng gõ chữ thời gian thực.

Tại sao cần HTTP Streaming trong AI?

$$ T_{\text{total}} = T_{\text{prefill}} + \sum_{i=1}^{M} t_{\text{decode}}^{(i)} $$

  • Mô hình LLM sinh $M$ token có thể mất từ 10 đến 30 giây
  • Blocking: Chờ sinh xong mới gửi, TTFB bằng $T_{\text{total}}$ gây trễ
  • Cơ chế Streaming: Sinh được token nào đẩy ngay qua socket về Client
  • TTFB giảm xuống chỉ còn $\sim 200\text{ms}$ ➔ Trải nghiệm gõ chữ mượt mà
Phân tích công thức độ trễ và tại sao TTFB (Time to first byte) lại là chỉ số vàng trong Generative AI.

Nguyên lý: HTTP Chunked Transfer

  • Sử dụng header HTTP Transfer-Encoding: chunked
  • Không cần biết trước tổng kích thước dữ liệu (Content-Length)
  • Kết nối TCP được giữ mở liên tục giữa FastAPI và Streamlit
  • Máy chủ liên tục đẩy từng mẩu byte qua socket ngay khi generator yield
  • Client giải mã từng chunk unicode và hiển thị ngay tức thì
Cơ chế kỹ thuật đằng sau HTTP Streaming và Server-Sent Events.

Frontend: Đọc Luồng Byte với Thư viện requests

frontend_app.py (Consumer) 

def client_stream_consumer():
    """Generator đọc từng chunk byte từ HTTP stream."""
    with requests.get(
        f"{API_BASE_URL}/predict-stream",
        params={"text": prompt.strip()},
        stream=True,  # QUAN TRỌNG: Giữ socket mở
        timeout=10.0
    ) as stream_resp:
        if stream_resp.status_code == 200:
            for chunk in stream_resp.iter_content(
                chunk_size=None, decode_unicode=True
            ):
                if chunk:
                    yield chunk
        else:
            yield f"Lỗi máy chủ: {stream_resp.status_code}"
Yielding chunks from network socket in real-time...
  • Cờ stream=True: Bắt buộc, báo requests không tải toàn bộ body về RAM
  • stream_resp.iter_content(): Lắng nghe socket và giải mã từng chunk unicode
  • Hàm này trở thành một Python Generator hoàn chỉnh phía Client
  • Bảo đảm đóng socket an toàn sau khi đọc xong nhờ context manager with
Lưu ý then chốt: Quên stream=True sẽ làm mất hiệu ứng streaming.

Lỗi Thường Gặp, Tổng Kết & Bài Tập

Bắt đầu Phần 5: Tổng kết bài giảng, điểm qua các lỗi hay gặp và giao bài tập về nhà.

Lỗi 1: Nhầm Biến thường & Session State

LỖI

Khai báo biến lưu kết quả dạng biến thường: results = []. Khi người dùng thao tác ở ô nhập khác, toàn bộ kết quả cũ biến mất không dấu vết do Streamlit rerun từ đầu.

SỬA

Luôn lưu dữ liệu vào st.session_state["results"]. Kiểm tra if "results" not in st.session_state: trước khi gán giá trị mặc định.

💡 Hãy nhớ: Coi session_state như chiếc két sắt bảo toàn dữ liệu qua các chu kỳ rerun.
Nhắc lại lỗi số 1 của người mới học Streamlit.

Lỗi 2: Mất Kết Nối Tới API Backend

LỖI

Bấm nút trên giao diện Streamlit bị báo lỗi đỏ: requests.exceptions.ConnectionError: [Errno 111] Connection refused.

SỬA

1. Quên chưa khởi động FastAPI bằng lệnh uvicorn backend_api:app --port 8000.
2. Nhầm lẫn cổng kết nối: Gõ nhầm cổng 8501 của Streamlit thay vì cổng 8000 của FastAPI. Kiểm tra http://localhost:8000/docs trước.

Nhắc học viên kiểm tra kỹ cổng và terminal uvicorn.

Lỗi 3: Lỗi Schema 422 từ Pydantic

LỖI

API trả về mã lỗi 422: {"detail":[{"loc":["body","text"],"msg":"field required"}]} dù đã có gửi dữ liệu lên.

SỬA

So khớp chính xác 100% tên khóa (keys) giữa Pydantic Model (text: str) và payload JSON gửi đi trong requests.post(json={"text": input}). Tránh nhầm với "content" hay "input_text".

Lỗi 422 thường do lệch tên trường giữa frontend và backend.

Lỗi 4: Mất Hiệu Ứng Typing Khi Streaming

LỖI

Dù backend dùng StreamingResponse nhưng Streamlit vẫn đợi 10 giây rồi phụt ra cả đoạn văn bản cùng một lúc.

SỬA

1. Đảm bảo bật cờ stream=True trong hàm requests.get().
2. Truyền trực tiếp hàm Generator vào st.write_stream thay vì truyền chuỗi tĩnh resp.text.

Điểm mấu chốt để st.write_stream hoạt động là phải có stream=True và generator yield.
